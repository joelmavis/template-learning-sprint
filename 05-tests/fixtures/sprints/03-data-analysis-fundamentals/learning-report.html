Rows, columns, and data typesInternal lesson ID: L01demonstrated

What was learned.

A reliable analysis begins by saying what one row represents. In the bundled order table, one row is intended to represent one order. units and unit_price are numeric; date is temporal; channel and region are categorical; returned is Boolean-like. order_id is an identifier even though it contains letters and digits.

Practice.

State the intended grain and classify order_id, date, units, and channel.

Learner submission.

One row is one order. order_id is text, date is a date, units is numeric, and channel is a category.

Feedback.

The classifications are correct. Calling order_id merely text misses its role: it is an identifier and should be checked for uniqueness at this grain.

Questions, metrics, and dimensionsInternal lesson ID: L02needs review

What was learned.

“Which channel performs best?” is ambiguous. Define the outcome and comparison: for example, total gross revenue (units × unit_price) grouped by channel, before returns. The metric is gross revenue; the dimension is channel. A decision-ready question also states time range and whether returned orders count.

Practice.

Rewrite “Which channel is best?” as a measurable question using the bundled table.

Learner submission.

Which channel has the highest average unit price?

Feedback.

This is measurable, but average unit price does not represent sales performance. A stronger choice is “Which channel has the highest gross revenue from 1–4 September, before adjusting for returns?”

Missing values and duplicatesInternal lesson ID: L03demonstrated

What was learned.

Cleaning is a decision, not automatic deletion. The table contains a missing region for O105 and a duplicated O106 row. If order_id should be unique, retain one O106 record after verifying the duplication. Keep O105 for overall revenue but label its region as unknown for regional summaries. Record both choices.

Practice.

Find the data-quality issues and state how each affects a channel summary and a regional summary.

Learner submission.

O106 appears twice, so I would remove one copy. O105 has no region, so I would delete it.

Feedback.

The duplicate rule is reasonable after confirming grain. Deleting O105 would understate store revenue. Keep it for channel totals and use an Unknown region for regional analysis.

Filtering and grouped summariesInternal lesson ID: L04needs review

What was learned.

Apply cleaning rules first, then calculate row revenue as units × unit_price. After removing the duplicated O106, gross revenue is: web 50 + 45 + 60 = 155; store 40 + 200 + 48 = 288; partner 50. Grouped totals answer a different question from average unit price.

Practice.

Calculate gross revenue by channel after applying the L03 rules.

Learner submission.

Web = 215, store = 288, partner = 50. Store is highest.

Feedback.

Store and partner are correct. Web double-counted O106; after deduplication it is 155. The conclusion remains store, but the error matters because it changes the margin.

Median, spread, and outliersInternal lesson ID: L05demonstrated

What was learned.

For unit price after deduplication, the values are 10, 12, 15, 25, 30, 40, and 200. The median is 25. The mean is about 47.4 because the 200 value pulls it upward. Neither is automatically correct: the median describes a typical listed value more robustly, while the mean remains relevant for some financial calculations.

Practice.

Compute or identify the median unit price and explain why the mean is higher.

Learner submission.

The median is 25. The mean is higher because 200 is far above the other prices.

Feedback.

Correct. The answer names both the robust center and the specific source of skew. Mastery is demonstrated for this small example.
